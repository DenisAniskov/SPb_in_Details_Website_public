# Петербург в деталях — исходный код официального сайта

Открытая копия исходного кода официального сайта Android-приложения
**«Петербург в деталях»**: презентация возможностей, официальная загрузка APK из
GitHub Releases, документы о конфиденциальности и лицензиях.

- Официальный сайт: <https://spb-in-details.vercel.app>
- Приложение и его исходный код: <https://github.com/DenisAniskov/SPb_in_Details_public>
- Опубликованный релиз: <https://github.com/DenisAniskov/SPb_in_Details_public/releases/tag/v1.1.1>
- Публичный backend: <https://github.com/DenisAniskov/SPb_in_Details_Backend_public>
- Репозиторий этого исходного кода: <https://github.com/DenisAniskov/SPb_in_Details_Website_public>
- Лицензия исходного кода сайта: [MIT](LICENSE) (границы применения — [`ASSET_RIGHTS.md`](ASSET_RIGHTS.md))

Этот репозиторий публикуется для открытого чтения исходников сайта. Он **не**
является источником автоматических production-развёртываний: сайт собирается и
публикуется из отдельного рабочего репозитория, а здесь лежит его открытая копия.

## Назначение репозитория

Здесь находится весь код, необходимый, чтобы собрать тот же статический сайт:

- страницы (`/`, `/privacy/`, `/legal/`, `404`, `robots.txt`, карта сайта);
- данные о текущем релизе приложения и правила их проверки;
- скрипты, которые сверяют данные о релизе и готовую сборку;
- генератор веб-ресурсов бренда из утверждённой иконки приложения.

## Стек

| Слой | Выбор |
| --- | --- |
| Генерация | Astro 7, `output: 'static'` |
| Язык | TypeScript (strict), проверка `astro check` |
| Стили | Один файл `src/styles/global.css`, без CSS-фреймворков; светлая и тёмная палитры на переменных |
| Данные | JSON в `src/data/` со схемой и проверками |
| Клиентский JS | Три маленьких файла: `public/theme.js` (тема до первой отрисовки), `public/ui.js` (копирование суммы, увеличение снимков), `public/menu.js` (закрытие мобильного меню) |
| Внешние запросы | Нет: шрифты системные, все ресурсы с того же домена, аналитики нет |

Страницы: `/` (главная), `/privacy/`, `/legal/`, `404.html`, `robots.txt`,
`sitemap-index.xml`.

## Требования

- Node.js **22.22.0** или новее (требование Astro 7).
- npm (идёт вместе с Node.js).

## Быстрый старт

```bash
npm ci                 # установка зависимостей
npm run dev            # локальная разработка, http://localhost:4321
npm run build          # сборка в dist/ + проверки после сборки
npm run preview        # просмотр собранного сайта
```

## Проверки и сборка

```bash
npm run check                        # типы: astro check (0 ошибок)
npm run verify:metadata -- --github  # данные о релизе против GitHub Releases
npm run build                        # сборка + постсборочные проверки готового dist/
npm run verify:dist                  # только постсборочные проверки (нужен dist/)
npm run verify                       # всё вместе: check → metadata → build
```

Чтобы дополнительно сверить данные о релизе с локально скачанным APK, передайте
путь к нему через `--apk` или переменную `SPB_APK_PATH`:

```bash
npm run verify:metadata -- --github --apk ./release-artifacts/SPb_in_Details_1.1.1+3_release.apk
```

Имя файла APK не зашито в скрипт: оно берётся из проверенного
`src/data/release.json`, поэтому сверить артефакт другой версии вместо текущего
невозможно. По умолчанию артефакт ищется в каталоге `release-artifacts/` рядом с
репозиторием; путь можно задать явно.

Что проверяет `npm run build` (скрипт `scripts/postbuild-check.mjs`):

- обязательные страницы, `robots.txt`, карта сайта и иконки на месте;
- каждая внутренняя ссылка, картинка, стиль и скрипт ведут на существующий файл;
  каждая внешняя ссылка использует HTTPS;
- canonical, `og:image`, `lang="ru"`, `noindex` у 404;
- кнопка загрузки указывает ровно на официальный файл релиза из
  `src/data/release.json`, и никуда больше;
- SHA-256, размер, версия, имя файла и отпечаток сертификата на странице
  совпадают с данными о релизе;
- в `dist/` нет APK, keystore, `.env` и похожих на секреты строк;
- в выводе нет встроенных `<script>` и `<style>` — это условие строгого
  Content-Security-Policy из `vercel.json`;
- на страницах нет ссылок на Google Play: приложение там не публикуется;
- тема оформления применяется до первой отрисовки и не мигает;
- переключатель оформления есть на каждой странице и доступен с клавиатуры;
- обе палитры объявлены в CSS полностью, а пары «текст на поверхности»
  проходят WCAG AA;
- скриншот показывается только с подтверждённым происхождением; у каждого
  опубликованного снимка есть `alt`, реальные `width`/`height`, `loading="lazy"`,
  ссылка на полноразмерный файл и диалог увеличения;
- в разделе вопросов есть ответы на все обязательные вопросы, включая честный
  «автоматических обновлений нет».

Ни одну из этих проверок не следует отключать, чтобы сборка «прошла»: они
защищают опубликованные сведения о релизе и происхождение изображений.

## Данные о релизе

Все сведения о версии, ссылках, размере и контрольной сумме берутся из трёх
файлов; в компонентах они не дублируются.

| Файл | Содержимое | Схема и проверка |
| --- | --- | --- |
| `src/data/release.json` | версия, сборка, тег, commit, ссылки, размер и SHA-256 APK, сертификат подписи, требования Android | `src/lib/release.ts` |
| `src/data/project.json` | авторство, идея, список функций, ограничения, техника, обязательные атрибуции | `src/lib/project.ts` |
| `src/data/screens.json` | слоты для скриншотов приложения и правила их публикации | `src/lib/screens.ts` |

Проверки запускаются при импорте (`src/lib/site.ts`) и останавливают сборку:
непустые обязательные поля, HTTPS-ссылки, формат SHA-256 и SHA-1, соответствие
тега версии, ссылка на APK внутри официального релиза того же репозитория,
`distribution.hostedOnThisSite = false`, известные иконки функций.

### Текущий выпуск

Сайт описывает опубликованный Android-релиз:

- версия `1.1.1`, сборка `3`, тег `v1.1.1`;
- файл `SPb_in_Details_1.1.1+3_release.apk`, размер `169835339` байт;
- SHA-256 `2a5004d8fa16fe5f2747fea0ea9a6ee5c0d8bdaf42803e25492a8fc2900a9d63`;
- commit Android-репозитория `6076d5bde3fdb34e0ba0ff049516016dc3621046`.

### Как выпустить новую версию приложения

1. Дождаться, пока релиз появится в GitHub Releases.
2. Обновить `src/data/release.json`: `version`, `build`, `gitTag`, `commitSha`,
   `publishedAt`, `apk.fileName`, `apk.sizeBytes`, `apk.sha256`, `urls.*`,
   при необходимости — блок `signature`.
3. Проверить: `npm run verify:metadata -- --github` (расхождений быть не должно).
4. Собрать: `npm run build`.
5. Отправить изменение отдельным коммитом — сайт переключится только после
   проверки и публикации. **Автоматического перехода на свежий релиз GitHub нет.**

## Прямое скачивание APK

Кнопка загрузки на сайте не размещает и не переупаковывает файл: она ведёт
напрямую в GitHub Releases приложения. Ссылка собирается из
`release.urls.apkDownload` и проверяется при сборке — она обязана указывать
внутрь официального релиза того же репозитория, а имя файла должно совпадать с
`apk.fileName`. Установка не требует аккаунта и регистрации.

## Скриншоты и их происхождение

Правило: на сайте появляются только изображения реального интерфейса
опубликованной версии. Макеты, чужие изображения и отрисовки из тестов за
скриншоты не выдаются.

**Одного файла в `public/screens/` недостаточно.** Наличие файла не подтверждает,
что на нём интерфейс приложения, поэтому изображение попадает на сайт только
вместе с описанием съёмки; сборка останавливается, если файл лежит в
`public/screens/`, а происхождение не указано.

Чтобы добавить снимок:

1. Снять экран на устройстве или эмуляторе: вертикальный кадр, не меньше
   320×480, формат PNG, JPEG или WebP.
2. Положить файл в `public/screens/` под именем из `src/data/screens.json`.
3. В этом же слоте заполнить `provenance` (`device-screenshot` или
   `emulator-screenshot`) и `capture`:

   ```json
   "provenance": "device-screenshot",
   "capture": {
     "device": "Pixel 6, Android 15",
     "capturedAt": "2026-10-19",
     "appVersion": "1.0.0",
     "build": 1
   }
   ```

   Подпись под изображением собирается из `provenance` и `capture`, а не
   пишется вручную: так она не может противоречить способу съёмки. `appVersion`
   и `build` сверяются с `src/data/release.json` — снимок другой сборки
   опубликовать нельзя. Единственное исключение — явный флаг
   `"archived": true` у слота: он разрешает показать честный архивный снимок
   **предыдущей** версии (данные `capture` остаются подлинными, а на странице
   снимок помечается архивным; версия новее текущей отвергается).

Сейчас в галерее — архивные снимки версии `1.0.0`, сборка `1`: физическое
устройство (POCO X6 5G), 20 октября 2026 года, слоты помечены `"archived": true`.
Сайт публикует релиз `1.1.1`. Снимки честно отмечены как изображения
предыдущего выпуска: они не выдаются за снимки текущей версии, а сравнение
старого и нового интерфейса не заявляется без отдельной проверки.

Что сборка отвергает:

| Случай | Что произойдёт |
| --- | --- |
| Файл есть, `provenance` = `null` | ошибка сборки с подсказкой заполнить `capture` |
| `provenance` указан, файла нет | ошибка сборки |
| Горизонтальный кадр | ошибка: снимок экрана телефона должен быть вертикальным |
| Изображение меньше 320×480 | ошибка |
| Формат не PNG/JPEG/WebP | ошибка |
| `capture.appVersion` или `build` ≠ релиз | ошибка (или флаг `archived` для предыдущей версии) |
| `capture` заполнен при `widget-test-render` | ошибка |

## Ресурсы бренда

Иконка приложения не перерисовывается. Favicon, иконка для главной, превью для
соцсетей и изображения разделов получены из утверждённых ресурсов приложения:

```bash
python tools/generate_web_assets.py --source-repo <путь к репозиторию приложения>
python tools/generate_web_assets.py --source-repo <путь> --check   # сверка без записи
```

Скрипт отказывается работать, если SHA-256 утверждённой иконки
(`docs/branding/original_app_icon.png`) не совпадает с зафиксированным, и пишет
манифест с контрольными суммами в [docs/BRAND_ASSETS.md](docs/BRAND_ASSETS.md).
Для `og-image.png` нужен каталог с `roboto-*.ttf`; путь к нему передаётся через
`--font-dir` (по умолчанию скрипт ищет `material_fonts/` рядом с репозиторием и
в `FLUTTER_ROOT`, если переменная задана).

## Что сайт намеренно не делает

- не размещает и не переупаковывает APK — кнопка ведёт в GitHub Releases;
- не собирает персональные данные, не подключает аналитику, рекламу и трекеры;
- не хранит в браузере ничего, кроме выбранной темы оформления, и не отправляет
  это на сервер;
- не показывает макеты или чужие изображения вместо скриншотов приложения;
- не объявляет новую версию актуальной без проверки и решения владельца;
- не заявляет, что приложение опубликовано в Google Play или проверено
  Google Play Protect.

## Структура

```
src/
  components/     секции страницы и общие блоки (Hero, Features, Showcase, Download, Faq, …)
  data/           release.json, project.json, screens.json
  layouts/        BaseLayout.astro
  lib/            схемы и проверки данных, форматирование
  pages/          index, privacy, legal, 404, robots.txt
  styles/         global.css
public/           favicon, brand-ресурсы, screens/*.png, theme.js, ui.js, menu.js, og-image.png
scripts/          проверки после сборки и сверка данных о релизе
tools/            генератор веб-ресурсов из утверждённой иконки
docs/             BRAND_ASSETS.md (происхождение ресурсов), DESIGN.md (дизайн и доступность)
```
